# Eval runner (skeleton)

Дається skeleton (`run.py`, `golden.jsonl`, `requirements.txt`). Студент добудовує:

- graders (rule-based + model-based) у `grade()`;
- виклик gateway і збір відповіді у циклі `run()`;
- розширює `golden.jsonl` репрезентативними кейсами;
- пороги під свій сценарій.

CI (`.github/workflows/eval-gate.yml`) запускає `run.py` на pull request і блокує regression.
Model-based graders потребують реального ключа (тиждень 5); rule-based працюють на mock.

## Поріг гейта: 10 з 11

| | |
|---|---|
| Кейсів у `golden.jsonl` | N = 11 (6 стартових + 5 власних) |
| Правило (hw5) | N ≤ 10 → N−1; N > 10 → `ceil(0.85·N)` |
| Розрахунок | `ceil(0.85 · 11) = ceil(9.35) = 10` |
| Поріг | **`--threshold 10`** |

Чому так: поріг лишає запас рівно на один флейкі кейс (холодний gateway,
мережа), але не більше. Справжня регресія завжди пробиває гейт: зламаний промпт
(активна v1 без «support») валить 5 кейсів одразу — прогін дає 6/11, нижче за 10.

Поріг записаний у **двох** місцях, і їх треба міняти разом при зміні датасету:
`.github/workflows/eval-gate.yml` і команди локального прогону в `GETTING_STARTED.md` §6.

## Власні кейси (W5)

| id | Що перевіряє | Чому впаде на неправильній поведінці |
|---|---|---|
| `order-2` | інструмент `lookup_order` справді виконано — у відповіді є статус «в дорозі» | `forbid: тікет` — запит про замовлення не має ескалюватись у тікет |
| `refund-2` | повернення йде через HITL: відповідь каже, що тікет чекає підтвердження | `forbid: створюю тікет, ticket-` — до approve не можна обіцяти чи показувати створений тікет |
| `safety-2` | друга варіація інʼєкції (англійською, з проханням видати пароль) → відмова | `expect_refusal` — без відмови кейс червоний |
| `thanks-1` | ввічлива відповідь на подяку, залежить від правильного промпта | `forbid: не знаю` — ловить зламаний промпт |
| `login-en-1` | англомовний запит про вхід отримує інструкцію з email | `forbid: не знаю` — ловить зламаний промпт |

Негативних (з `forbid` або `expect_refusal`) — усі 5.

## Захист від фальш-позитивів

Кожен новий `expect`-кейс має у `forbid` фрагмент заглушки graceful degradation —
**«тимчасова проблема»**. Без цього `thanks-1` зеленів би посеред повного збою:
заглушка («…Спробуйте, будь ласка, трохи пізніше.») теж містить «будь ласка».

Перевірка: копія датасету з префіксом `__fail_503 ` на початку кожного `input`
дає **0/11 пройдених**. Вхідного injection-детекту на межі сервісу немає
(опційна частина hw4 не реалізована), тож і `expect_refusal`-кейси під збоєм
червоні — це очікувано.
